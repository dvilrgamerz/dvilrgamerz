# Security Policy

## Scope

This policy covers the DVILR SPEED web application in this directory.

## Reporting a vulnerability

Please do not publish an unpatched security vulnerability in a public issue. Contact the repository owner privately through GitHub's available private/security reporting mechanism when one is enabled for the repository.

When reporting, include:

- A clear description of the issue
- Affected page/file and approximate location
- Reproduction steps or a minimal proof of concept
- Security impact
- Browser/OS information when relevant
- Suggested remediation, if known

Do not include passwords, API keys, access tokens, personal information, or other real secrets in a report.

## Response expectations

Reports will be reviewed as reasonably possible. Security fixes may require verification, testing, and a new deployment before public disclosure.

## Safe testing

Only test systems you own or have explicit permission to test. Do not attempt denial-of-service testing, credential attacks, data theft, destructive testing, or access to other users' data.

## No absolute security guarantee

DVILR SPEED is a static browser application. Security controls reduce risk but cannot guarantee that the application is invulnerable. New browser, hosting, dependency, configuration, or supply-chain vulnerabilities can arise over time.
